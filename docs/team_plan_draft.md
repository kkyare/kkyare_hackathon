## 1. 한 줄

> **현실의 규정과 날씨를 넣으면, AI가 실측으로 자동 채점되는 RL 환경을 몇 초 만에 만들어 내는 공장.**
> 첫 번째 환경은 미국 대형농의 농약 살포 결정이다.

- 돈 내는 쪽: RL·Eval 데이터 회사(Scale, Surge, Mercor, Handshake, Turing), AI 랩
- 정답 도메인: 미국 대형농 (선언 타깃) - 실제 날씨와 실제 규정
- 같은 엔진의 2차 사업: 농장·살포업자용 SprayWindow (판단 + 준수 기록)

## 2. VC가 기억할 장면 (데모의 목표)

발표 3분 안에 아래 다섯 장면 중 최소 세 개가 "우와"를 만들어야 한다.

| # | 장면 | 왜 충격인가 |
|---|---|---|
| 1 | **규정 문서를 붙여 넣으면 30초 만에 RL 환경이 생긴다** | "사람이 몇 주 걸려 만드는 걸 AI가 30초에" - 데이터 회사 원가 구조를 뒤집는 장면 |
| 2 | **과제 1,000개가 실시간으로 쏟아지고, 카운터 옆에 시장가 $가 올라간다** | 무한 공급 + 돈. 과제당 시장 단가 $200-2,000 |
| 3 | **최신 AI 모델들이 같은 과제를 풀다가 줄줄이 틀린다** | "최고 모델도 34%" 같은 숫자 = 랩이 살 이유(headroom) |
| 4 | **타임머신: 예보가 바뀌고 진짜 날씨가 도착하면서 AI의 판단이 실시간으로 채점된다** | 지도 위 애니메이션, 현실이 채점자라는 걸 눈으로 본다 |
| 5 | **AI가 채점기를 속이려 하고, 감사 AI가 잡아낸다** | RL 업계 1순위 고민(reward hacking)을 정면으로 해결 |

마무리: **"이 패키지는 지금 바로 Surge에 보낼 수 있습니다"** → 내보내기 버튼.

## 3. 기능 목록

우선순위: **P0** = 없으면 데모 불가 / **P1** = 와우 장면 / **P2** = 시간 남으면

### A. Environment Studio (규정 → 환경 컴파일러) - 장면 1
| 우선 | 기능 |
|---|---|
| P0 | 라벨 텍스트 붙여넣기 → Claude가 규칙 JSON 추출 (풍속, 돌풍, 기온 상한, 50% 면적, 강수, 풍향·민감작물, 일출~일몰) |
| P0 | 추출된 규칙을 카드로 표시, 각 규칙에 원문 문장 하이라이트 연결 (근거 추적) |
| P1 | 규칙 → 판정 코드 자동 생성 + 샘플 날씨로 즉시 테스트 실행 |
| P1 | 미리 준비한 예시 3종 버튼: dicamba 2026 / glufosinate / **농업이 아닌 규정 1종**(예: 드론 비행 풍속 제한) → "농업은 첫 사례일 뿐" |
| P2 | PDF 업로드 |

### B. Task Factory (과제 공장) - 장면 2
| 우선 | 기능 |
|---|---|
| P0 | 지역·기간·작업 유형·개수 선택 → 과제 생성 (필지 × 날짜 × 규칙 조합) |
| P0 | 과제 = t0 시점 예보 스냅샷 + 필지 정보 + 규칙 + 질문 + 채점 함수 |
| P1 | 생성 과정 스트리밍: 카운터, 지도에 점이 찍히는 애니메이션, "시장가 환산 $" 실시간 증가 |
| P1 | 난이도 자동 분류: 예보와 실측이 갈린 정도, 경계값(9-11mph 등) 비율 → 쉬움/보통/어려움 분포 그래프 |
| P1 | **Buyer Copilot**: "바람 방향 전환 재계획 과제, 통과율 10-30%로 500개" 같은 자연어 주문 → 조건에 맞는 패키지 생성 |
| P2 | 과제 패밀리 추가: 서리 대응, 파종 시기, 관개 |

### C. Model Arena (모델 경기장) - 장면 3
| 우선 | 기능 |
|---|---|
| P0 | 같은 과제 묶음을 모델 2-3개(Claude 등)에 실행, tool use(예보 조회, 필지 조회, 규칙 조회) |
| P0 | 모델별 점수표: 규정 준수율, Brier, 결정 손익(regret, $), 스킬 점수 |
| P1 | 병렬 실행 화면: 모델별 레인에 추론 과정이 실시간으로 흐름 |
| P1 | **Headroom 차트**: 모델별 통과율 분포 → "아직 아무도 못 푸는 구간"이 보이게 |
| P1 | 틀린 사례 상세: 모델 판단 vs 실제 날씨 vs 규정, 어디서 틀렸는지 한 줄 요약(Claude) |
| P2 | 보정 곡선(reliability diagram) |

### D. Time Machine (리플레이) - 장면 4
| 우선 | 기능 |
|---|---|
| P0 | 2026년 6월 아이오와 하루 재생: 시간 슬라이더 |
| P0 | 지도 위 필지 색 = 판정(GO/CAUTION/NO-GO), 시간에 따라 변함 |
| P1 | 예보 갱신(이전 런 → 다음 런)과 실측 도착을 겹쳐 보여 줌, AI 판단이 맞았는지 필지마다 ✓/✗가 뜸 |
| P1 | 바람 화살표, 강수 레이어 애니메이션 |
| P2 | 같은 날을 "단일 모델만 봤다면"과 비교 |

### E. Hack Hunter (꼼수 사냥) - 장면 5
| 우선 | 기능 |
|---|---|
| P1 | Red-team 에이전트가 채점기 허점 공격: 50% 면적 쪼개기, 예보 도구 반복 호출로 유리한 값 고르기, 규정 문구 해석 꼼수 |
| P1 | 감사 에이전트(규칙 + Claude)가 적발 → 적발 목록, 탐지율 |
| P1 | 채점기 패치 전/후 diff와 버전 기록 → "우리 채점기는 이렇게 단단해진다" |

### F. Ops Board (농장용 SprayWindow) - 2차 사업 장면
| 우선 | 기능 |
|---|---|
| P1 | 필지 38개 지도 + 필지 × 시간 히트맵 |
| P1 | Claude 브리핑: 살포기 2대 작업 순서, 50% 면적 배분, 보류 이유 |
| P2 | 질문하기, 준수 기록 CSV/PDF |

### G. Export & Pricing (납품) - 마무리
| 우선 | 기능 |
|---|---|
| P0 | 패키지 내보내기: 과제 JSON + 채점 함수 + 데이터 카드(출처, 기간, 난이도 분포) |
| P1 | Prime Intellect `verifiers` 형식 호환 |
| P1 | 가격 계산기: 과제 수 × 시장 단가, 독점 시 4-5배 |
| P2 | 공개 리더보드 공유 링크 |

## 4. 채점 설계 (모든 기능의 공통 심장)

| 층 | 시점 | 계산 | 의미 |
|---|---|---|---|
| ① 규정 준수 | 즉시 | 결정 시점 예보에 규칙 적용 | 정책을 지키는가 |
| ② 결과 | 사후 | 실측 관측에 같은 규칙 적용 → Brier, 비용-손실 regret | 현실에서 맞았는가, 돈이 됐는가 |
| ③ 스킬 | 사후 | 원천 예보를 그대로 따랐을 때 대비 개선 | 예보 복사 = 0점 |
| ④ 무결성 | 즉시 | Hack Hunter 감사 결과 | 높은 점수 = 진짜 실력 |

- 같은 판정 엔진을 예보에 돌리면 "판단", 실측에 돌리면 "정답". 엔진 하나로 제품(F)과 환경(B·C·D)을 모두 만든다.
- 비용-손실 예: 살포 비용 C, 비산·재살포 손실 L → P(위반) > C/L 이면 보류가 최적 (`attentionx-weather-rl-gym.md` 2-3 참고)

## 7. UI 참고

### 톤
- **"연구소 장비 + 트레이딩 터미널"** 느낌. 다크 모드 기본, 숫자는 크고 고정폭, 색은 판정 3색 + 강조 1색만.
- 판정 색: GO 초록 / CAUTION 노랑 / NO-GO 빨강. 그 외 UI는 무채색으로 눌러서 판정이 튀게.
- 움직임이 곧 임팩트: 카운터 증가, 점 찍힘, 스트리밍 텍스트, 슬라이더 애니메이션.

**1장 - "AI는 코드는 채점하는데, 현실은 못 한다"**
- 랩 RL 환경 지출 (연 $1B+ 논의), 과제 단가 $200-2,000, 코드 밖은 채점이 병목
- 기존 농업·기상 벤치마크는 정적 문항 / 실측 채점 라이브 환경은 없음 (찾지 못함)
- 날씨 = 매시간·모든 지점에서 수치로 확정되는 정답

**2장 - "규정과 날씨를 넣으면 환경이 나온다"**
- 데모 장면 캡처 3개 (Studio · Arena · Time Machine)
- 채점 4층 (준수 · 결과 · 스킬 · 무결성)
- 사업: 데이터사 환경 피드·맞춤 환경 → 2차로 농장 SprayWindow → 규정 있는 다른 운영(에너지, 물류, 드론)
- 숫자: 최고 모델 통과율, 생성 과제 수, 시장가 환산

## 10. 정직하게 표시할 것

- 라벨 규칙은 데모용 예시이며 실제 라벨이 우선한다 (화면 문구로 표시)
- 날씨·농업 RL 환경을 이미 산 구매자는 확인되지 않았다 → "수요 검증 중"으로 말하고, 일반화(규정 있는 운영 전반)를 근거로 든다
- 모델 점수는 오늘 실제로 돌린 결과만 보여 준다. 캐시는 REPLAY 배지
- Open-Meteo 무료 API는 비상업 용도, 출처 표기
