## 1. 판단 기준별 결과

| 기준 | 결과 | 근거 강도 |
|---|---|---|
| 직무가 실재하나? | ✅ 실재한다. GROWMARK FS, Five Star Coop, Agtegra, AgState, Wilbur-Ellis 등 8곳 이상에서 공고를 확인했다. 시급은 약 $21~28이다 | 중간. 공고 스니펫 기준이고, 대형 retailer 공고는 못 찾았다 |
| 날씨 재배차가 주요 고통인가? | 🟡 업계 공통 고통으로 보인다. 다만 빈도 수치는 없다 | 약~중간. 인용이 2011~2019년 자료다 |
| 기존 소프트웨어가 이미 하나? | ✅ **배차 자체는 이미 있다.** Agvance SKY, Raven Slingshot/AgSync, Deere Ops Center PRO, Solinftec | 강함 |
| 날씨 기반 자동 재계획은 빈칸인가? | ✅ **찾지 못했다.** 기존 제품은 날씨를 표시·기록할 뿐이고, 재스케줄은 드래그앤드롭 수동이다 | 중간. 없음을 증명한 것은 아니다 |

**결론**: 배차를 처음부터 만들면 Agvance, Raven과 정면으로 붙는다. **"날씨·라벨 규칙이 바뀌면 자동으로 재계획하고 연락까지 하는 AI 레이어"**만 빈칸이다.

## 2. 고통의 근거

**시즌이 압축된다**
- "보통 10~12주인데 3~4월을 통째로 날렸다… 6주 정도밖에 없다." (Kentucky retailer, CropLife 2011)
- "가동하면 24/7 일하게 되고, 모두에게 스트레스가 된다." (같은 기사)

**정보가 늦게 전달된다**
- Agvance 자료에 따르면 작업이 수천 건 적체되고 "hurry-up-and-wait"가 반복된다. applicator와 dispatch 사이에 정보가 늦게 전달되면서 오류가 생긴다.

**인력이 부족하다**
- ag retailer의 60%가 labor를 최대 과제로 꼽았다.
- applicator 기본급은 5년간 26% 올랐다.
- "사람을 구할 수 없어 custom application 사업을 팔았다." (CropLife)
- 이 근거는 **사람 1명이 더 많은 일을 처리하게 해 주는 자동화**의 필요로 이어진다.

**규모**
- ARA 2024 표본에서 location당 custom 처리 면적은 약 53,000 acre다.
- Nutrien은 1,500개 지점, Helena는 475개 지점을 운영한다.

## 3. 데모와 데이터에 미치는 영향

| 항목 | 결정 |
|---|---|
| 포지셔닝 | "새 배차 시스템"이 아니라 **Agvance·AgSync 같은 기존 시스템 옆에서 도는 재계획 에이전트**로 둔다 |
| 차별 기능 | ① 문자·전화 주문 파싱 ② 날씨·라벨 이벤트 기반 자동 재계획 ③ 기사·농가 메시지 초안 |
| 민감 작물 | FieldWatch는 공개 API가 없다. **mock registry**를 쓰고, 덱에서 "FieldWatch 파트너 연동"을 로드맵으로 언급한다 |
| 멸종위기종 구역 | EPA Bulletins Live! Two에는 공개 REST·ArcGIS API가 있어 실제 조회가 가능하다(Stretch). 단 EPA는 이 API가 라벨 준수용 BLT를 대체하지 않는다고 명시했다 |
| 라벨 규칙 | 강우 제한이 출처마다 4시간·48시간으로 다르다. 240ft buffer는 2차 출처다. **라벨 원문 확인 전에는 "예시 기준"으로 표기한다** |

## 4. 트랙(3번, RL Eval·데이터사)과의 연결

팀 README에 따르면 트랙의 돈 내는 쪽은 RL Eval·데이터 회사다. 이 결과는 유진 님의 FieldBench 구조에 이렇게 들어간다.

- **농장 쐐기 제품**: 재계획 에이전트를 applicator와 retailer의 dispatcher에게 판다.
- **RL 환경 과제**: 똑같은 배차·재계획 문제를 과제로 쓴다. 다중 필지, sprayer 용량, 50% 면적 규칙, 주문 마감, 중간 예보 갱신이 들어간다. 장기·도구 사용형 에이전트 과제가 되고, **실측 날씨로 자동 채점**한다.
  - 채점 지표: 위반 살포 건수(false-go), 처리 면적, 마감 준수율
- 이 결과가 보강하는 근거: 기존 배차 소프트웨어는 재계획을 사람 손에 맡긴다. 그래서 **"이 판단을 잘하는 에이전트"를 평가·학습할 환경이 필요하다**는 논리가 선다.
